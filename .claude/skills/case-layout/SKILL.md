# Вёрстка кейсов — харнес

Кейсы бывают двух видов. Сначала определяем вид, затем читаем **его файл целиком** и верстаем строго по нему.

| Вид | Что это | Правила | Шаблон | Эталон |
|---|---|---|---|---|
| **Продуктовый** | Моя работа в компании: шапка с годами, тегами и обложкой, задачи, навыки, сценарии «до / после», итоги с цифрами. Тёмная тема | `product.md` | `product-template.mdx` | Betting (`betting.mdx`); также «Метр квадратный», Quantori |
| **Прожарка** | Раздел «Отраслевая прожарка»: проблемы реальных пользователей отрасли и решение на живых экранах телефона. Светлая тема, своя вёрстка | `roast.md` | `roast-template.mdx` | «Агрегаторы авиабилетов» (`skyway.mdx` → `components/case/skyway/`) |

Кейс с главной из плиток «Альфа Банк / Betting / Quantori / Метр квадратный» — **Продуктовый**; из раздела «Отраслевая прожарка» — **Прожарка**. Если неясно — спросить пользователя.

## Общее для обоих видов

- **Кегли и отступы текста вне экранов — одни и те же токены** (`--text-display`, `--text-case-body`, `--case-label-size`, `--text-tile-title`, `--case-*-gap`), переопределены для модалки в `.case-drawer__scroll` (`CaseDrawer.astro`). Не хардкодим.
- Кейс открывается в модалке поверх главной (`CaseDrawer.astro`); раскладка — по ширине контейнера `case` (`@container case (min-width: 800px)` — две колонки, `max-width: 599px` — телефон).
- RU и EN — всегда вместе, EN пишем сами параллельно.
- Типографика (CLAUDE.md): висячих предлогов нет (`typograph()` / hast-плагин), без точки в конце последнего предложения, если дальше нет текста, тире не начинает строку, ранних переносов нет (`text-wrap: balance` не используем).
- Числа (CLAUDE.md): целые px, интервал чётный через `--lh`, отступы кратны 2px.
- Цифры — из материалов пользователя или известных исследований; придумываем только по прямой просьбе и отмечаем это в CLAUDE.md.
- Картинки — через `asset()`, WebP 2x, исходники в `design/cases/<slug>/`, без `loading="lazy"`.
- Скрипты кейса — `init…(body)` в `CaseDrawer.astro` в обоих местах (открытие кликом и прямой заход).
- Работаем шагами: показали → согласовали → дальше. Новое правило, утверждённое пользователем, — **сразу дописываем в файл своего вида** (`product.md` или `roast.md`), общее — сюда.
- После шага: `pnpm build` → проверка в браузере на 1728 / 1440 / 1024 / 390 → коммит → пуш → деплой в Cloudflare и Яндекс → обновить CLAUDE.md → обе ссылки пользователю.
