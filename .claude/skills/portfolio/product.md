
# Продуктовый кейс

Эталон — кейс **Betting** (`src/content/{ru,en}/cases/betting.mdx`). Новый кейс собираем **из тех же компонентов, на тех же токенах, по тем же правилам**. Ничего не хардкодим: только токены `--case-*` из `src/styles/tokens.css`. Если в макете пользователя значение отличается от токена — берём токен, а расхождение показываем пользователю и спрашиваем.

Раздел харнеса портфолио. Шаблон — `product-template.mdx`. Общие правила (типографика, числа, тексты, картинки, модалка, проверки, деплой) — в `SKILL.md`, здесь только своё для продуктовых кейсов.

## 0. Порядок работы

1. Взять артборд/файлы пользователя (Figma — только источник контента и картинок, дизайн делаем кодом).
2. Создать `src/content/ru/cases/<slug>.mdx` и `src/content/en/cases/<slug>.mdx` **одновременно** (EN пишем сами, параллельно).
3. Собрать структуру по разделу «Скелет кейса» из компонентов ниже.
4. Картинки — по разделу «Картинки» (исходники в `design/cases/<slug>/`, сайт — `public/images/cases/<slug>/`).
5. Связать с плиткой на главной (`TILE_CASES`, `TILE_IMAGES`, `TILE_LEADS` в `src/components/Tiles.astro`, тексты в `src/i18n/ui.ts`).
6. Проверить по чек-листу (раздел 9), затем коммит → пуш → деплой в оба места (см. CLAUDE.md).
7. Шагами: показали → согласовали → дальше.

## 1. Где и как показывается кейс

Модалка, поля панели, раскладка по контейнеру — общие для всех кейсов, см. `SKILL.md` → «Кейс в модалке».

## 3. Типографика (размеры в модалке, на 1728px)

Шрифт — Onest. Правила чисел из CLAUDE.md обязательны: целые px, интервал чётный (через `--lh`), отступы кратны 2.

| Элемент | Кегль / интервал | Начертание |
|---|---|---|
| Заголовок кейса | `--text-display` 58 / 52 | 600 |
| Годы `period` | `--text-case-body` 17 | 400, `--case-muted` |
| Теги | `--text-case-body` | плашки, скругление `--case-tag-radius` 8px |
| Текст | `--text-case-body` 17 / 28 | 400, `--case-muted` |
| Заголовок раздела `##` | `--text-tile-title` 32 / 36 | 600, `--tracking-title`, белый |
| Подпись под `##` (следующий абзац) | `--case-label-size` 15 | капс, `--tracking-label` |
| «До / После» `###` | `--text-case-body` | 400, капс, жёлтый, по центру |
| Подписи к картинкам | `--text-case-body` | 500, белый, обычный регистр |
| Числа воронки | `--case-metric-size` 36 | 800 |
| Вкладки | `--case-label-size` | 500, капс |

Текст:
- **Красная строка** у абзацев (`--case-indent` 12px), кроме подписей, капса, чисел.
- В шапке кейса между абзацами — пустая строка; **внутри сценария (`CaseTabs`) — без пустой строки**, только красная строка.
- Вводный текст можно обернуть в `<div class="case-lead">…</div>` — тогда и в шапке абзацы без пустой строки (так в Quantori, по просьбе пользователя). По умолчанию в шапке — с пустой строкой (Betting, «Метр квадратный»); единого правила пользователь пока не утвердил — для нового кейса спросить.
- Списки: маркер под первой буквой абзаца, текст через `--case-bullet-gap` 20px; пункты с заглавной, без «;» и «.» в конце.
- `**жирный**` выглядит как обычный текст.
- Висячие предлоги — автоматика (`typograph`); ничего руками. Числа с единицами («2,5 раза») — неразрывный пробел.
- Повествование: командная работа — «мы», личная — «я». Цифры — сверенные (см. раздел 8).

- **Заголовок кейса с обложкой — не шире левой колонки** (`(100% − --case-col-gap) / 2` на широком контейнере), даже если обложка опущена ниже заголовка (правило в `CaseArticle.astro`).

## 5. Скелет кейса

```
frontmatter: title, description, date, period, tags, theme: dark, slides | cover
Шапка: годы → заголовок → теги → вводный текст (рядом — обложка/слайдер) → TextColumns «Передо мной стояло…» → Chips
CaseTabs (вкладки сценариев; выбранный — слот, остальные «Кейс в разработке»)
  ## Сценарий «до и после» (по центру)
  ### До → Flow → схема/экраны
  ### После → Flow → схема/экраны
  ## Разделы… (по центру; «текст + картинка рядом» — слева)
  ## Итоги + подпись → Metrics → Flow с итогами
```

Заголовки разделов и подписи под ними — **по центру**, кроме заголовка над `Columns` с картинкой рядом.

## 6. Компоненты (`src/components/case/`)

| Компонент | Когда | Ключевое |
|---|---|---|
| `Flow` | **Любой сплошной текст в две колонки** | Перетекает из левой в правую, колонки **равны по строкам** (подгоняем текст: проверить на 1728 и 1440). Не делим по смыслу. |
| `Columns` | Текст + картинка рядом | Две колонки от 800px контейнера; `center` — текст по середине высокой картинки; заголовок раздела можно поставить внутрь левой колонки (`## ` в `<div>`) — тогда заголовок и текст вместе по центру картинки, сверху у блока отступ раздела 80px |
| `TextColumns` | Список задач «Передо мной стояло…» | Жёлтым, вводная + две колонки списков; `flow` — один длинный пункт без `<Columns>`, перетекает в две колонки; `wrap` — рядом с высокой обложкой (без `clear`, в одну колонку, без «дырки» под текстом) |
| `Chips` | Навыки | Прозрачные с обводкой; `clear` — во всю ширину под обложкой; `split={N}` — первые N строкой рядом с обложкой, остальные сразу под ней (24px) |
| `CaseTabs` | Селектор сценариев | `items`, `active`; 2 × 2 на телефоне. Без `items` — селектора нет, только стили сценария (заголовки по центру, отступы) |
| `CoverSlider` | Обложка-слайдер (`slides`) | Экраны 2x/3x, автопрокрутка 4с, соседи яркостью 55% |
| `Screens` | 3 экрана в ряд | `<имя>-{616,924}.webp`; на телефоне — лента |
| `Figure` | Картинки | см. ниже |
| `Soon` | Заглушка «Кейс в разработке» | Для вкладок и этапов без содержимого (`CaseTabs`, переключатели схем) |
| `quantori/DrugReport` | «Живой» экран продукта из плоского SVG | Окно браузера с прокруткой внутри: куски картинки 2x + интерактив кодом поверх (вкладки, сворачивание, тултипы как в макете, наведение). Сборка — `design/cases/quantori/drug-report/` (`measure.mjs` → `build.py` → `render.mjs`). Образец, если пользователь попросит «сделай интерактивным, как сайт» |
| `ChartTabs` | Несколько графиков в одном месте | Вкладки как селектор сценариев Betting (жёлтая выбранная), содержимое — `<div slot="t0">…</div>`, без JS |
| `Metrics` | Воронка | `sets` («Старая / Новая») или `items`; анимация роста и досчёт процентов |
| `quantori/Scale` | Масштаб продукта крупными цифрами | Полоски растут, числа досчитывают; серые подписи справа над концом полоски; можно ставить во всю ширину сразу под обложкой (`data-cover-below`) |
| `quantori/Results` | «Было → стало» по истории | В стиле `Scale`: крупное жёлтое «стало», справа название и серое «было N», полоска стало/было; цифры пропорциональные (не `tabular-nums`); наборы — в `data.ts` |
| `quantori/StockChart`, `RevenueChart`, `PatentChart` | Рабочий график продукта кодом | По SVG-макетам состояний пользователя: меню, легенды, тултипы, навигатор; данные придуманы детерминированно (только по просьбе); свёрстан в 1120px и масштабируется `zoom`, на телефоне не уже 760px — листается вбок; `init*` в CaseDrawer |

`Figure`:
- `caption` — подпись над картинкой;
- `side` — рядом с текстом в `Columns`, уходит за правый край панели (и на телефоне);
- `wide` — широкая схема: на узком не мельчит, листается (мин. 960px);
- `scroll` — лента экранов высотой `--case-strip-h` (402px на 1728), `strip={k}` — высота ×k (0.7, 1.2); `loop` — карусель в край панели, по кругу, по центру;
- `box` + `zoom` + `tiles` — большая карта: рамка `--case-figure-box-h` 600px, таскается мышью, колесо листает кейс; картинки больше ~8000px — **плитками** (`scenarios-tiles.py`).

Правило полей: контент не выходит за поля, **кроме** `side`, `loop` и того, что пользователь явно попросит. **На телефоне (<600px) всё, что листается вбок** (схемы, `wide`, ленты, `Screens`, `box`, цепочки), уходит за правый край экрана (правило в `CaseArticle.astro`; новые листаемые блоки — добавить туда).

Воронка `Metrics` на телефоне — целиком на экране, уменьшена пропорционально (`--u` = 100cqi / 812), подписи переносятся как в макете.

Обложка в шапке (`centerCover` в CaseDrawer): по вертикали — посередине между верхом годов и текстом под ней; если первая строка заголовка шире левой колонки — обложка начинается ниже неё (`minTop`); высокая обложка — рядом `TextColumns flow wrap` и `Chips split`, без пустого места под текстом.

Всё, что оживляет кейс скриптом, подключается в `CaseDrawer.astro` **в обоих местах** — при открытии кликом и при прямом заходе (`init…(body)`).

Общие правила (форматы, 2x, `asset()`, исходники, размытие чужих логотипов) — `SKILL.md` → «Картинки». Здесь только своё:

## 8. Тексты и цифры

Общие правила текста — `SKILL.md` → «Тексты». Своё:

- Принудительный перенос во вторую колонку `Flow` — продолжение абзаца в `<p class="case-flow__next">…</p>` (без красной строки).
- **Цифры — только из материалов пользователя.** Ничего не придумывать (ни «до», ни промежуточных шагов воронки): если данных нет — спросить или строить график из того, что есть.
- Цифры сверять между собой во всём кейсе: графики ↔ текст ↔ превью на главной.
  - Разница процентов — **п. п.** (в кейсе), относительный рост — **%** (на превью); не смешивать («48% п. п.» — нельзя).
  - Знаки «<» и «>» с числами — без окончаний: «<2 минут», не «<1ой минуты».
- **Подписи столбиков `Metrics` — максимум 2 строки** на 1728 / 1440 / 1024 / 390, RU и EN; длиннее — переписываем короче (не мягкими переносами). Проверка — скрипт подсчёта строк подписей в браузере. `\n` — для принудительного переноса.
- Описание кейса на главной — 3 строки на 1728 (длина как у остальных карточек, «без ёлки»).
- Картинка плитки на главной — как у Betting: 1200 × 1632, прозрачный фон, центральный экран 560px (x 320, y 0), боковые 82% (459 × 994, x 90 и 651, y 120), из экранов обложки `cover-*-1125.webp`.
- **Картинки всех плиток — на одном уровне по высоте**: верх композиции (верхний край самого высокого экрана или карточки) — y 0 холста 1200 × 1632. Десктопные продукты (Quantori) — карточки экранов внахлёст по референсу пользователя (`design/cases/quantori/tile.py`), верх первой карточки — тоже y 0.
