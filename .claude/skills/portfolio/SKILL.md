# Харнес портфолио

Один харнес на весь сайт. Здесь — **общие правила** для всего; правила конкретной части — в разделах рядом. Перед работой читаем этот файл и **раздел своей части целиком**.

| Раздел | Что | Файл | Шаблон | Эталон |
|---|---|---|---|---|
| **Главная** | Hero, плитки кейсов, «Обо мне», «Отраслевая прожарка» | `home.md` | — | `HomeContent.astro` |
| **Продуктовый кейс** | Моя работа в компании: шапка с годами, тегами и обложкой, задачи, навыки, сценарии «до / после», итоги с цифрами. Тёмная тема | `product.md` | `product-template.mdx` | Betting; также «Метр квадратный», Quantori |
| **Прожарка** | Проблемы реальных пользователей отрасли и решение на живых экранах телефона. Светлая тема, своя вёрстка | `roast.md` | `roast-template.mdx` | «Агрегаторы авиабилетов» |

Кейс из плиток главной (Альфа Банк / Betting / Quantori / Метр квадратный) — продуктовый; из «Отраслевой прожарки» — прожарка. Неясно — спросить.

**Журнал решений** — `log.md`: подробная история каждого блока сайта (значения, файлы, что утверждено, что отклонено и почему). Перед правкой блока — найти его там; после шага — дописать решение туда. Правило в харнесе важнее записи в журнале.

## 1. Работа

- Шагами: маленький шаг → показали → согласовали → дальше. Если просят «покажи текст сначала» — только текст в чате, без публикации.
- Новое правило, утверждённое пользователем, — **сразу в харнес**: общее — сюда, частное — в раздел своей части.
- Отклонённые варианты не возвращаем (они записаны в `log.md`).
- После шага решение дописываем в `log.md` (в запись своего блока), в CLAUDE.md обновляем только строку «Задеплоено».
- После каждого шага: `pnpm build` → проверка в браузере → коммит → пуш → деплой в Cloudflare и Яндекс → обновить CLAUDE.md → обе ссылки пользователю (CLAUDE.md → «Деплой»).

## 2. Числа и токены

- Только токены из `src/styles/tokens.css` (и `--case-*`, переопределённые для модалки в `.case-drawer__scroll`). Не хардкодим; нужен новый размер — новый токен.
- Целые px; кегли плавные — `round(clamp(…), 1px)`; межстрочный — множитель `--lh` (`--leading-*`), px считает `reset.css` с округлением до 2px; отступы и размеры кратны 2px (`round(…, 2px)`); трекинг — `--tracking-*`. Исключение — линии 1px.
- Шрифт Onest: заголовки разделов главной 800, заголовки кейсов 600, текст 400.
- **Один и тот же элемент — одним токеном везде**: текст кейса, подписи, заголовки разделов и отступы между блоками одинаковые во всех кейсах любого вида.
- Цвета: у главной и продуктовых кейсов — общие токены; у кейса прожарки — **своя палитра отрасли** (переменные на обёртке кейса, `roast.md`). Это не нарушение правила токенов: общими остаются кегли, интервалы и отступы.

## 3. Тексты

- RU и EN — всегда вместе (EN пишем сами, параллельно). Тексты — только через `ui.ts` + `t()`, MDX или `typograph()` (`copy.ts` кейса — через `deep()`, по кускам между тегами).
- Висячих предлогов нет — автоматика (`typograph`, hast-плагин), руками не расставляем; тире не начинает строку; ранних переносов нет (`text-wrap: balance/pretty` и ширину в `ch` не используем); аббревиатуры (UI, ИИ) не привязываются.
- **Без точки в конце последнего предложения**, если дальше нет текста (заголовки, подписи, плашки, пункты списков, подсказки, конец абзаца перед картинкой).
- **С заглавной буквы**: заголовки, подписи, плашки, бейджи, пункты списков, строки после «·» («Бесплатно на Флекс», «Вылет 06:40»).
- Списки вместо сплошного перечисления через двоеточие и точку с запятой.
- Человеческие слова, без канцелярита и жаргона, понятно без объяснений; если пользователь не понял фразу — переписываем, а не объясняем.
- Большие числа — цифрами: «235 000», «100 000 ₽», не «235 тысяч».
- Единицы не отрываются от числа (`4 040 ₽`, `2,5 раза` — неразрывный пробел); «<2 минут» без окончаний.
- Цифры — из материалов пользователя или известных исследований (с источником); придумываем только по прямой просьбе и отмечаем это в CLAUDE.md. Цифры сверяем по всему сайту: графики ↔ текст ↔ превью на главной.

## 4. Картинки

- Пользователь кладёт файлы через GitHub (`public/images/` или корень) — исходник переносим в `design/cases/<slug>/` (латиницей), на сайт — WebP в `public/images/cases/<slug>/`; сборочные скрипты храним рядом с исходником.
- SVG → Chromium (Playwright, 2–3x) → sharp WebP; PDF → PyMuPDF с прозрачностью; огромный PNG → sharp `limitInputPixels: false`; SVG > 25 МБ — просим PDF. Разрешение — 2x от размера на сайте (экраны 2x/3x через `srcset`).
- Все ссылки — через `asset()` (метка версии от кэша Яндекса). В кейсах — без `loading="lazy"`.
- Логотипы и названия чужих компаний на скринах — размываем (кроме заказчика, если пользователь не скажет иначе).
- Текст в SVG бывает контурами — правим заменой на `<text>` тем же шрифтом.

## 5. Кейс в модалке (оба вида)

- Кейс открывается в модалке поверх главной (`CaseDrawer.astro`): панель справа `--case-panel-w` (70vw, мин. 860px / 80vw / весь экран), поля `--case-panel-gutter` 80 / 48 / 20px — слева, справа, сверху и снизу. Прямой заход по адресу кейса — главная + сразу открытая модалка; кейс всегда открывается с начала.
- Раскладка — **по ширине контейнера кейса** (`@container case (min-width: 800px)` — две колонки, `max-width: 599px` — телефон), не экрана.
- Ссылка на кейс — с `data-case-link` (открывается в модалке).
- Скрипты кейса — `init…(body)` в `CaseDrawer.astro` **в обоих местах** (открытие кликом и прямой заход).
- Листаемое вбок (ленты, схемы, карты) на телефоне уходит за правый край; ленты экранов — в край модалки, в покое первый экран по полю.
- Сплошной текст в две колонки — по правилам `Flow`: колонки равны, абзацы без пустой строки, красная строка `--case-indent`, маркер списка под первой буквой абзаца; правая колонка не начинается с одного-двух слов.
- Отступы между блоками — `--case-tabs-section-gap` 80px; заголовок раздела — `--text-tile-title` 600; подпись к картинке — `--text-case-body` 500, до картинки `--case-caption-gap`.

## 6. Выход в край и макеты — пометки в разметке

- **`data-edge`** — блок, которому можно выходить за поля (фон hero, бегущая строка, ленты и карусели `Figure scroll/loop`, `Figure side/wide/box/bleed`, `Screens`, схемы `OldFlow`, `UserPath`, цепочка `StatusChain`, лента экранов прожарки). Новый блок, который должен уходить в край, — **сразу с `data-edge`**, иначе `check:layout` его поймает. Всё остальное — строго в полях.
- **`data-mockup`** — макет чужого интерфейса внутри кейса (экраны телефона прожарки, отчёт и графики Quantori): повторяет отступы своего продукта, поэтому сетка 2px сайта к нему не применяется. Кегли целые и интервалы чётные — и в макетах тоже.
- `data-bleed` — другое: блок, чей **фон** идёт в край, а содержимое держит поля само (hero, кейс, модалка).

## 7. Поведение

- Наведение — только для мыши (`@media (hover: hover)`); плитки на наведении приподнимаются, ссылки со стрелкой ↗ сдвигают стрелку.
- Каждое движение — с вариантом для `prefers-reduced-motion` (стоит / сразу на месте).
- Фокус с клавиатуры виден (`:focus-visible`), после клика мышью рамки нет.
- Высоты экрана — `svh`/`lvh`, не `dvh`.

## 8. Проверка

- **`pnpm check:layout`** (при запущенном `pnpm preview`): главная и все кейсы, RU и EN, 1728 / 1440 / 1024 / 390 — ловит горизонтальную прокрутку, хвост в начале правой колонки, точку/«;» в конце заголовков, пунктов, подписей и плашек, подписи воронки длиннее 2 строк, дробные кегли и нечётные интервалы, **отступы не кратные 2px** (padding, gap, вертикальные margin) и **выход за поля** (видимая часть с учётом обрезки). `--self-test` — проверка самих проверок (все 7 должны срабатывать). Новая ошибка, которую поймал пользователь, — по возможности добавить в скрипт.
- Скриншоты в браузере на **1728 / 1440 / 1024 / 390**, RU и EN (Playwright, `pnpm preview`); телефон — эмуляция iPhone.
- Ничего не за полями (кроме оговорённого), колонки равны, подписи не длиннее нужного числа строк.
- `pnpm build` — проходит и проверяет типографику (сборка с висячим предлогом не выкладывается).
