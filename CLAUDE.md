## Типографика (всегда, везде)

- **Висячие предлоги, союзы и частицы не допускаются — никогда и нигде.** Короткое слово всегда автоматически переносится на новую строку вместе со следующим; тире не начинает строку. Руками ничего не расставляем — всё делает автоматика:
  - строки интерфейса: `useTranslations` → `typograph()` (`src/i18n/typograph.ts`): после слов из 1–2 букв и служебных из 3 (для, без, над, под, при, про, или, что, как, чем, где, это; the, and, for, but…) — неразрывный пробел, перед «—»/«–» — тоже;
  - тексты кейсов (Markdown/MDX): hast-плагин `typographPlugin` (`src/i18n/rehype-typograph.ts`) в обработчике Sätteri (`markdown.processor` в `astro.config.mjs`). В Astro 7 старые `rehypePlugins` Sätteri **молча пропускает** — плагины только в его формате (`hastPlugins`);
  - аббревиатуры из двух заглавных (UI, ИИ, UX) не привязываются — иначе цепочка «UI и разная» становится одним неразрывным куском и переносится раньше времени, оставляя пустое место в строке;
  - пропсы и всё, что выводится мимо `t()` (заголовок и теги кейса, подписи, чипсы, метрики), — через `typograph()`.
- Новые тексты — только через `ui.ts` + `t()`, MDX или `typograph()`.
- **Никаких ранних переносов**: слово не уходит на новую строку, если помещается в предыдущую. Поэтому `text-wrap: balance/pretty` и ограничения ширины в `ch` у текста не используем. Проверка — `scripts/check-wraps.mjs` (браузер: все блоки текста на главной и в кейсе при 1728/1440/1024/390, учитывает обтекание картинки); аббревиатуры (UI, ИИ) к следующему слову не привязываются.
- **Проверка в сборке**: `pnpm build` в конце запускает `scripts/check-typograph.mjs` — обходит весь текст страниц в `dist/` и падает, если после короткого слова или перед тире стоит обычный пробел. Сборка с висячим предлогом не выкладывается.

## Дизайн-система: правила чисел (всегда, везде)

- **Только целые пиксели** — никаких ,5 и дробных значений (в CSS, токенах, координатах схем).
- **Кегль** — целое число px: плавные размеры в токенах пишем в px и оборачиваем в `round(clamp(…), 1px)`.
- **Межстрочный интервал — всегда чётное число px.** `line-height` напрямую не пишем: компонент задаёт множитель `--lh` (токены `--leading-display` 1.02, `--leading-title` 1.1, `--leading-tight` 1.2, `--leading-lead` 1.5, `--leading-body` 1.6), а общее правило в `src/styles/reset.css` (`* { line-height: round(calc(var(--lh) * 1em), 2px) }`) считает интервал от кегля элемента и округляет до 2px.
- **Отступы кратны 2px** — `margin`, `padding`, `gap`, `inset`/`top`/…, размеры блоков; плавные и em-значения — `round(…, 2px)`; вместо rem — px.
- **Трекинг** — целые px: `--tracking-display` `round(-0.03em, 1px)`, `--tracking-title` `round(-0.02em, 1px)`, `--tracking-label` `round(up, 0.02em, 1px)`.
- Исключения: толщина линий и обводок (1px) и координаты ,5 у 1px-обводок в SVG (чтобы линия ложилась ровно в пиксель).
- Проверка: скрипт в браузере обходит все элементы (главная, модалка кейса, страница кейса; 1440/1024/390) — дробных кеглей, нечётных интервалов и отступов нет (2026-09-28).

## Сетка (обязательно для всех страниц и компонентов)

- **Поля контента** — `--gutter`: **160px** слева и справа от 1280px, **100px** на планшетах (768–1279px), **20px** на мобильных. Контент за поля не заходит. Фоны (например, градиент hero) могут идти в край — такие блоки помечаются `data-bleed`, а их собственный контент держит поля сам.
- **Шапка** — полоса `--header-h` = **64px** сверху, зафиксирована (при скролле на месте). Элементы шапки центрируются по вертикали в этих 64px и по горизонтали не выходят за `--gutter`.
- Значения — только токены из `src/styles/tokens.css`, не хардкодим.

### Временная сетка (dev-оверлей)

Модуль `src/components/DevGrid.astro`: вертикальные линии по полям на всю высоту + горизонтальная линия на 64px от края до края, контрастные к фону (`mix-blend-mode: difference`). Флаг — `DEV_GRID` в `src/config/dev.ts`.

## Деплой (Cloudflare Pages)

Когда пользователь говорит «задеплой», делаем всё по этой инструкции **без переспрашивания**. Пользователь не должен повторять её заново.

**Деплоим сразу после каждого завершённого шага** (не дожидаясь «задеплой»): коммит → пуш → деплой → проверка → ссылка пользователю. **Деплой — всегда в два места**: Cloudflare Pages (шаг 4) **и** зеркало Yandex Object Storage (шаг 4б, для России). Пользователю даём обе ссылки, для РФ главная — https://vadimpianov.website.yandexcloud.net/ru/

- Проект Cloudflare Pages: **`vadimpianov`**, production-ветка **`main`**, адрес **https://vadimpianov.pages.dev**
- Ключи — в переменных окружения облачного окружения: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`

### Шаги

1. **Подготовить ключи.** Значения могли быть сохранены в угловых скобках (`<…>`). Wrangler такие отвергает, поэтому перед командами снимаем скобки и пробелы:
   ```sh
   export CLOUDFLARE_ACCOUNT_ID="$(printf %s "$CLOUDFLARE_ACCOUNT_ID" | tr -d '<> ')"
   export CLOUDFLARE_API_TOKEN="$(printf %s "$CLOUDFLARE_API_TOKEN" | tr -d '<> ')"
   ```
   (Правильнее исправить сами значения в настройках окружения — сказать об этом пользователю, если скобки есть.)
2. **Собрать** (из корня репозитория):
   ```sh
   pnpm install --frozen-lockfile && pnpm build
   ```
3. **Проверить, что проект существует; если нет — создать:**
   ```sh
   npx wrangler pages project list
   npx wrangler pages project create vadimpianov --production-branch main   # только если его нет
   ```
4. **Выложить в production** — строго из корня репозитория, чтобы вместе с `dist/` задеплоилась папка `functions/` (редирект по языку):
   ```sh
   npx wrangler pages deploy dist --project-name vadimpianov --branch main
   ```

4б. **Выложить зеркало для России** (Yandex Object Storage, тот же `dist/`):

```sh
pnpm deploy:yandex
```

5. **Проверить:**
   ```sh
   curl -sSI https://vadimpianov.pages.dev/ru/   # 200
   curl -sSI https://vadimpianov.pages.dev/en/   # 200
   curl -sS -o /dev/null -D - https://vadimpianov.pages.dev/   # 302, Location: /en/ (или /ru/ из РФ)
   ```
   Для `/` — именно GET, не `curl -I`: функция обрабатывает только GET, на HEAD отдаётся статический `index.html` (200).
   И зеркало:
   ```sh
   curl -sSI https://vadimpianov.website.yandexcloud.net/ru/   # 200
   curl -sSI https://vadimpianov.website.yandexcloud.net/en/   # 200
   ```
   (Прокси окружения изредка рвёт соединение — `Connection reset by peer`; повторить с `--retry 3`.)
6. **Обновить «Состояние проекта»** ниже: дата деплоя, адрес. Закоммитить и запушить.

### Если не выходит

- **`fetch failed` / 403 от прокси на `api.cloudflare.com`**: это сетевая политика облачного окружения. Сказать пользователю: меню окружения в заголовке сессии → Edit → Network access → добавить в разрешённые домены `api.cloudflare.com` и `vadimpianov.pages.dev` (или выбрать уровень доступа шире). Не обходить.
- **`Invalid account ID "<…>"`**: см. шаг 1.
- **`Invalid format for Authorization header` [6111]**: в `CLOUDFLARE_API_TOKEN` лежит не API-токен (например, значение с `|` или Global API Key). Нужен API Token: dash.cloudflare.com → My Profile → API Tokens → Create Token → шаблон «Edit Cloudflare Workers» (или Custom: Account → Cloudflare Pages → Edit). Попросить пользователя заменить значение в настройках окружения.
- В CLAUDE.md не писать «задеплоено», пока шаг 5 не прошёл.

## Зеркало для России (Yandex Object Storage)

`*.pages.dev` и сайты на Cloudflare в РФ режутся (DNS-блок `pages.dev` у части провайдеров, с 2025 — обрыв соединений с Cloudflare после 16 КБ). Поэтому сайт дополнительно выкладывается в **Yandex Object Storage** (бесплатный лимит, 0 ₽/мес): адрес **https://vadimpianov.website.yandexcloud.net**. После каждого деплоя в Cloudflare — выкладываем и сюда.

- Скрипт: `pnpm deploy:yandex` (`scripts/deploy-yandex.mjs`, после `pnpm build`): сам создаёт бакет `vadimpianov` (если нет), публичное чтение, хостинг сайта (index.html в папках), заливает `dist/` с типами и кэшем, удаляет лишнее.
- Ключи — статический ключ сервисного аккаунта Yandex Cloud (роль `storage.admin`) в переменных окружения облачного окружения: `YC_ACCESS_KEY_ID`, `YC_SECRET_ACCESS_KEY` (скрипт сам снимает `<>` и пробелы). Новые переменные видны только **в новой сессии**.
- Сеть окружения: в Network access должны быть разрешены `storage.yandexcloud.net` и `vadimpianov.website.yandexcloud.net` (для проверки).
- Корень `/` на Яндексе без функции Cloudflare: `dist/index.html` (`src/pages/index.astro`) уводит на `/ru/` или `/en/` по cookie `lang`, иначе по языку браузера.
- Проверка: `curl -sSI https://vadimpianov.website.yandexcloud.net/ru/` и `/en/` → 200.
- Скрипт работает с адресацией через путь (`forcePathStyle`) — поддомен бакета `vadimpianov.storage.yandexcloud.net` в сети окружения не нужен.
- Выложено (2026-09-28, первый запуск): https://vadimpianov.website.yandexcloud.net — `/ru/`, `/en/`, `/` отдают 200. Проверено: HTML, CSS, JS, фото, логотипы — 200 с правильными типами; HTML `no-cache`; `/ru` → 302 на `/ru/`; содержимое совпадает со сборкой.

## Состояние проекта

Скаффолд готов (2026-09-25): Astro 7 + TS (strict) + MDX + i18n `/ru/`, `/en/` + GSAP/ScrollTrigger + Lenis + View Transitions.

- `pnpm dev` / `pnpm build` (включает `astro check` и проверку типов `functions/`) / `pnpm format`
- `functions/index.ts` — редирект с `/`: cookie `lang` → страна (`RU` → `/ru/`) → `/en/`
- `src/i18n/` — строки интерфейса (`ui.ts`), хелперы ссылок, выборка кейсов по локали
- `src/content/{ru,en}/cases/*.mdx` — кейсы. Типографика в MDX — hast-плагин Sätteri `src/i18n/rehype-typograph.ts` (в `astro.config.mjs`, см. «Типографика»)
- **Страница кейса** `src/pages/[lang]/cases/[slug].astro`: шапка кейса (годы `period`, заголовок, теги `tags` — цветные плашки по порядку `--case-tag-1` (зелёный #2fa802), `--case-tag-2` (малиновый #ad0063), скругление `--case-tag-radius` 8px, кегль и начертание как у текста кейса; чипсы навыков `Chips` — прозрачные с обводкой `--case-chip-border`, поля по бокам `--case-chip-pad-x` 12px; заголовок кейса — вес 600; отступ годы → заголовок — `--case-hero-gap` 12px, заголовок → теги — вдвое больше, 24px, между тегами — 16px (удвоенный `--chip-gap`), теги → текст (и теги → обложка на узком) — `--case-lead-gap` 32px; **красная строка** у абзацев текста кейса — `--case-indent` `round(0.75em, 2px)` (12px), кроме подзаголовков капсом, подписей и чисел; между абзацами — пустая строка (1em), списки и пункты списков — без промежутков; пункты списков с заглавной буквы и без знаков в конце (без «;» и «.»); маркер списка — под первой буквой абзаца (на красной строке, свой `::before`), текст пункта — через `--case-bullet-gap` 20px; `TextColumns` — жёлтым `--case-accent`, вводная строка + `<Columns>` с двумя списками (у Betting слева 2 пункта, справа 1), пункты колонок на одном уровне; до чипсов навыков — `--case-chips-gap` 24px, между чипсами — 16px со всех сторон, как между тегами; начало абзаца отмечает красная строка; `**выделение**` в тексте кейса выглядит как обычный текст — без белого цвета и жирности), тема `theme: dark` (тёмно-синий фон `--case-bg`, акцент `--case-accent` #fcd537). **Шапка кейса с обложкой** (`cover`): на широком контейнере (≥800px) обложка справа (`float`, 40%), по вертикали — посередине между верхом годов и текстом под ней (`centerCover` в CaseDrawer: отступы сверху и снизу равны, текст обтекает с самой картинки — `shape-outside: inset(отступ 0 0 0)`; блок под обложкой — `TextColumns` с `clear`; если текст рядом короче обложки — обложка вровень с годами); рядом — годы, заголовок, теги и первый текст кейса (в MDX — обычный текст сразу после импортов), ниже обложки текст во всю ширину; следующий блок `<TextColumns>` (clear) — текст, перетекающий в 2 колонки; на узком (и в модалке) — всё в колонку, обложка под тегами. Текст hero реагирует на скролл с задержкой: первые `TEXT_HOLD` (15% экрана) стоит на месте, потом плавно трогается (ease power1.out, без рывка); растворяется (1 → 0) и исчезает, когда целиком уходит под шапку
